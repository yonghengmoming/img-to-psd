imgtopsd — 图片还原为分层、中文可编辑 PSD
版本：1.2.1
更新日期：2026-10-04

一、用途与边界

将海报、详情页、广告图等平面图片重新整理成 Photoshop 多层文件，供后续修改。
背景、人物、商品、照片、图标、装饰等按实际内容分层；中文、数字、价格、标注等识别后重建为原生文字层。
这是依据成品图重新还原，不是找回原设计工程。被遮挡的背景、原始字体、矢量路径、图层样式和智能对象未必能恢复。
没有的元素不补造；无法独立恢复的阴影、光效可随所属图片保留，并注明。

二、三条必须遵守的规则

规则 1：PSD 像素尺寸必须与原图相同。
先读取源图宽 W、高 H，再以 W×H 建立 PSD。不得擅自放大、缩小、裁剪或改变比例。
原图有 DPI/PPI 信息时尽量保留；像素宽高与打印分辨率应分别核验，不能只比较文件大小或厘米尺寸。
例如原图为 761×1014 像素，交付 PSD 也必须是 761×1014 像素。

规则 2：横排、竖排及倾斜中文必须识别并建立原生可编辑文字层。
包括标题、正文、图片内标注、编号、价格、便签等。保持阅读顺序、方向、位置、颜色及尽可能接近的字号、行距和字体。
Photoshop 中应能识别为文字类型，并能用文字工具修改正文；像素文字、图层名称、SVG、PPTX 或单独文案文件不能替代这一要求。
清除底图上的旧文字并补底，避免修改文字后露出旧字。不要把旧字完整保留在可见图片层中，再叠加另一套文字。
竖排须按列识别，重建对应文字方向或逐字可编辑布局；不能仅把横排截图旋转后当作竖排文字层。

规则 3：无法识别的文字，用 ♦️ 代替。
经放大查看、对照或 OCR 复核后仍无法可靠识别的字，不猜测、不补写、不根据上下文改造成通顺句子。
能确定缺失字数时，每个不明字使用一个 ♦️；无法确定字数时，用一个 ♦️ 表示该段不明文字，并在说明中标记“字数不明”。
例如：“请提前♦️知客服”“修改♦️次”。示例仅演示占位，不代表本项目的实际文案。
PSD 原生文字内容、文案文件、文字清单中的占位必须一致，不能只在旁边备注而保留猜测文字。
准确字符为 ♦️（U+2666 加 U+FE0F）。应检查所用字体能显示；必要时对该字符单独指定支持字体，仍须保持可编辑。
不得用“待核对”、问号、方框或推测文字替代这个约定的占位符。可以另附位置说明，方便用户补字。
若使用原图文字像素作为预览缓存，必须同步更新含 ♦️ 的文字层缓存和合成预览，不能出现文字数据是 ♦️、画面仍显示旧模糊字的情况。

三、开始前准备

1. 核对用户本次指定的完整源图路径，尤其区分“给客户”“给客服”等相近文件名。
2. 读取实际宽高、色彩模式、透明度和分辨率；记录源文件校验值或其他可核验标识。
3. 保留原文件。明确输出路径，在有写入权限的位置生成文件。
4. 查看原图，划分栏目和元素，建立文字识别清单与图层规划。
5. 检查当前 Python、NumPy、Pillow、PSD 库及 Photoshop 是否真正可用，不把旧说明中的“已安装”当作当前验证结果。

四、文字识别与复核

1. 对标题、正文、小字、价格、编号、倾斜便签和图片内标签逐区检查，必要时放大局部。
2. 采用视觉识别、OCR 或二者结合；本目录不保证已内置 OCR 引擎。
3. 校对中文、数字、货币单位、标点、顺序和换行。收费、次数、工期、退款条件尤其不能凭经验修正。
4. 原图能辨认的语病或错字按原样保留，除非用户要求改文案。
5. 无法识别的位置按规则 3 写入 ♦️，并记录所在栏目、图层名及大致坐标。
6. 文案清单建议包含：图层名、正文、方向、旋转角度、x/y、宽高、字体、字号、颜色、行距及占位位置。

五、拆分图片与修复背景

1. 分离人物、产品、参考照片、图标、装饰及可恢复的阴影，输出有透明度的图像素材。
2. 矩形裁切不等于精细抠图；保留原背景、白边或阴影的素材需如实标明。
3. 擦除旧文字后近似修补背景。便签、胶囊标签、彩色卡片上的字，应以该元素自身底色补底，不能直接填白或让其透出其他背景。
4. 检查隐藏文字后的图像，确认没有可辨认的旧字残留；必要时继续修补。
5. 若导出紧边界 PNG，另存其在原始画布中的 x/y 和宽高，便于重新组装。

六、选择 PSD 生成路线

A. 纯像素图层
原有 make_psd.py 使用 pytoshop、NumPy、Pillow 生成像素图层，可作为图片分层基础。
它没有原生文字层、OCR、自动拆图或背景补全功能，单独执行不能满足本流程的可编辑文字要求。
其默认命令只生成三层演示，不能把源图路径当作现成图片转换参数使用。

B. Photoshop 原生文字（优先）
在 Photoshop 可用时，通过 COM、JSX 或受支持的自动化方式创建图层和文字对象，再由 Photoshop 保存 PSD。
可先测试 Photoshop.Application.200；该标识与安装版本相关，不能假定所有电脑都相同。
COM 注册存在不等于能够启动。先用小文档验证中文输入、保存、重开、改字，再批量处理。

C. 支持原生文字数据的离线 PSD 写入器
Photoshop 自动化不可用时，可使用经过验证的写入器生成原生文字对象，包括 Unicode 正文、字体、字号、方向、变换及相应文字引擎数据。
仅向文件写入 TySh 标记或能回读中文，并不足以证明 Photoshop 内可以正常编辑。
离线工具可能需要 Photoshop 更新文字层；字体替代和重排可能改变字形。未经应用内验证的文件须标为“应用内编辑未验证”，不能宣称全面通过。
若现有工具不能可靠创建原生文字，明确说明限制，不以像素文字冒充完成。

七、组装与保存

1. 按实际栏目建立分组，放入背景、图片、图标和原生文字。
2. 设置文字内容、字体、字号、颜色、方向、旋转和位置；对 ♦️ 检查显示及编辑能力。
3. 原图对照层可以保留，但默认隐藏，避免遮住实际分层结果。
4. 使用简单重叠色块验证所用库的上下层顺序，不仅凭 append 顺序或名字顺序判断。
5. 同步生成正确的合成图和 PNG 预览，避免出现图层正常而文件预览全黑。
6. 先写临时输出并验证，成功后再确定最终文件名，避免失败时留下伪装成成品的文件。

八、验收

文件检查：
- PSD 宽、高与源图严格一致；检查色彩模式及分辨率。
- 回读图层数、分组、可见性、位置、透明度与中文图层名。
- 每个文字区块都有对应原生文字对象；正文与识别清单一致。
- ♦️ 在文字数据、清单、图层渲染和合成预览中一致。
- 隐藏对照层后重组图层，检查整体外观、遮挡、缺字和重影。

Photoshop 应用内检查：
- 打开文件，检查文字层被识别为 T 类型。
- 在临时副本中实际修改一段中文和一个 ♦️，保存、关闭、重开后再次核对。
- 检查横排、竖排或倾斜文字的方向，字体和段落排版；本次不存在的方向不要虚报验证。
- 原文件不用于破坏性试改；验证结束关闭或单独保留测试副本。

结果记录：
分别记录尺寸检查、文字数据回读、预览检查及应用内改字检查是否通过。
缓存图层与原图逐像素一致，只证明该缓存的外观一致，不证明文字编辑功能。
替换 ♦️、使用近似字体或修补背景后，允许出现有原因的像素差异；应说明差异区域，不能同时声称整图逐像素无差异。

九、交付

必须提供：多层 PSD、与最终文件一致的 PNG 预览、简短使用说明。
按需要附带：透明 PNG 素材、可复制文案、文字和图层位置清单、占位符位置清单、校验结果及 ZIP 包。
说明原图尺寸、文字层数量、近似字体、补底限制、♦️ 的位置和未完成的验证。
最终回复提供实际存在的文件链接，不把尚未成功写入的位置说成已保存。

十、本机历史经验（需按当前环境复核）

- 曾使用 Python 3.11、pytoshop 1.2.1、NumPy 和 Pillow。pywin32 仅 COM 路线需要。
- 某个 Python 环境的 NumPy DLL 曾无法加载，另一个可用运行时可正常执行。先测试导入，不擅自修复或覆盖用户环境。
- 曾出现 Photoshop COM 启动失败，因此此前离线生成的原生文字 PSD 没有完成 Photoshop 内实际改字验证。
- pytoshop 的图层通道键使用 ChannelId，图像通道对象使用 ChannelImageData。
- 图层边界按 top、left、bottom、right 填写；不同接口的 size 参数需查当前代码并用非正方形图片验证。
- 本机某次安装缺少 packbits 扩展，RLE 压缩失败，改用 raw。不要把这一现象推广为所有安装都不支持 RLE。
- 无压缩 PSD 体积可能较大；先保证文件有效，需要时由 Photoshop 另存压缩。
- 中文图层名应写入 Unicode 图层名信息，不能只依赖旧式名称字段。
- make_psd.py 的回读仅比较名称，不能代替像素、文字类型和改字验证。
